## Board

The Orca panel reads `{{paths.board}}`. Update it in the same step as `state.md`, every time, through `B` (it validates the shape):

- Every action that waits on {{person.name}} (merge, ask a review, create a flag, click, decide) is a decision: `B ask "<ticket>" --repo <repo> --url <url> --action "Merge" --context "<what>" --options "done:Merge*|skip:Skip|explain:Explain"`. The action badge says what to do; the main button is the same verb in imperative; clicking it means {{person.name}} did it. Anything else waiting on {{person.name}}'s "post" is a decision too, added in the turn it is shown. `B answer <id> <option>` or `B decision:rm <id>` when it is done.
- Tasks are work items (tickets, issues, PRs): `B task:add <ticket> --ws <parent> --repo <repo> --status local|pr|hold|blocked|merged --pr <n> --url <url> --detail "<next>"`. `--url` is the item's own link, as the tool you used gave it (the ticket's, or the PR's once there is one); the panel never builds links, so an item without `--url` has none. Workstreams are parent tickets or features (`B ws:add`). Repos are other PRs (`B repo:add`). Agents list the live Orca workers from `worker-list` on their own; `B agent:set <name> working --id <dispatch>` is only for agents Orca does not report. `B focus "<one line>"`, `B log "<short>"` (last 20 kept).
- Priority items (urgent or time-critical: escalations, incidents) get `--oncall` (the flag's name is kept for compatibility); the panel shows a priority badge, labelled `{{board.oncallLabel}}` when set.
- Panel clicks arrive as terminal text: `<option> <decision id>`, `nudge <ticket>`, `stop <agent name>`. Act on them the same turn.
- The panel's "Clean up" (⋯ menu) runs `{{paths.bin}}/cleanup` directly, no model: a dry run (`-n`) first, the real run only after {{person.name}} confirms. If {{person.name}} types "cleanup now", run that script yourself (one command), not a worker.
